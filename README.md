# Sunservice · Подбор автомобилей

Лендинг услуги профессионального подбора автомобиля для автотехцентра
Sunservice, Дзержинск. Next.js 16 (App Router), TypeScript strict,
Tailwind CSS v4, PostgreSQL + Prisma, собственная админ-панель.

Проектные решения, разбор референсов и модель данных — в [`docs/PLAN.md`](docs/PLAN.md).

## Быстрый старт

Требуется Node.js **20.9+** и PostgreSQL 14+.

```bash
npm install
cp .env.example .env      # заполнить DATABASE_URL и AUTH_SECRET
npm run db:deploy         # применить миграции
npm run db:seed           # наполнить контентом
npm run dev
```

Сайт — http://localhost:3000, админка — http://localhost:3000/admin

### Без базы данных

Проект намеренно переживает отсутствие PostgreSQL: если `DATABASE_URL` не задан
или база недоступна, сайт отдаёт содержимое из `src/content/defaults.ts`, а
сборка проходит. Это удобно для вёрстки и обязательно для CI, но заявки при этом
не сохраняются, а админка показывает предупреждение.

## Переменные окружения

Полный список с комментариями — в [`.env.example`](.env.example).

| Переменная | Обязательна | Назначение |
| --- | --- | --- |
| `DATABASE_URL` | для работы с базой | строка подключения PostgreSQL |
| `NEXT_PUBLIC_SITE_URL` | да в production | canonical, OpenGraph, sitemap |
| `AUTH_SECRET` | да в production | ключ HMAC для отпечатков сессий |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `ADMIN_NAME` | для сида | первый администратор |
| `STORAGE_DRIVER` | нет | `local` (по умолчанию) или `s3` |
| `S3_*` | при `STORAGE_DRIVER=s3` | доступ к объектному хранилищу |
| `LEAD_WEBHOOK_URL`, `LEAD_WEBHOOK_SECRET` | нет | передача заявок во внешнюю систему |

Секрет для `AUTH_SECRET`:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

## База данных

PostgreSQL. Быстрый локальный запуск:

```bash
docker run -d --name sunservice-pg -p 5432:5432 -e POSTGRES_USER=sunservice -e POSTGRES_PASSWORD=sunservice -e POSTGRES_DB=sunservice postgres:16-alpine
```

Строка подключения для такого контейнера:

```
DATABASE_URL="postgresql://sunservice:sunservice@localhost:5432/sunservice?schema=public"
```

Команды:

| Команда | Что делает |
| --- | --- |
| `npm run db:deploy` | применяет готовые миграции (production и первый запуск) |
| `npm run db:migrate` | создаёт новую миграцию после правки схемы (разработка) |
| `npm run db:seed` | наполняет базу содержимым по умолчанию, идемпотентно |
| `npm run db:studio` | Prisma Studio — аварийный прямой доступ к данным |
| `npm run db:generate` | перегенерировать клиент Prisma |

Сид можно запускать повторно: существующие записи не перезаписываются, дубликаты
не создаются.

## Администратор

Первый администратор создаётся сидом из `ADMIN_EMAIL` / `ADMIN_PASSWORD`
(пароль от 8 символов) либо отдельной командой:

```bash
npm run admin:create -- admin@sunservice-auto.ru "надёжный-пароль" "Имя"
```

Та же команда меняет пароль существующему администратору и завершает все его
активные сессии.

Пароли хранятся только в виде bcrypt-хэша (12 раундов). Сессия — случайный токен
в httpOnly-cookie; в базе лежит его HMAC-отпечаток, поэтому доступа к дампу базы
недостаточно, чтобы выпустить рабочую сессию. Срок — 30 дней со скользящим
продлением. Вход ограничен: 10 попыток на адрес за 15 минут.

## Хранилище изображений

Абстракция в `src/lib/storage`. Драйвер выбирается переменной `STORAGE_DRIVER`.

**`local`** (по умолчанию) — файлы кладутся в `public/uploads`. Подходит для
разработки и для одного сервера с постоянным диском. Не переживает
пересоздание контейнера.

**`s3`** — любое S3-совместимое хранилище: Yandex Object Storage, MinIO,
Cloudflare R2. Реализовано без AWS SDK: подпись Signature V4 считается
средствами `node:crypto`, адресация path-style.

```env
STORAGE_DRIVER="s3"
S3_ENDPOINT="https://storage.yandexcloud.net"
S3_REGION="ru-central1"
S3_BUCKET="sunservice-media"
S3_ACCESS_KEY_ID="..."
S3_SECRET_ACCESS_KEY="..."
S3_PUBLIC_URL="https://sunservice-media.storage.yandexcloud.net"
NEXT_PUBLIC_ASSET_HOST="sunservice-media.storage.yandexcloud.net"
```

`NEXT_PUBLIC_ASSET_HOST` нужен, чтобы `next/image` разрешил домен для оптимизации.
Бакет должен допускать публичное чтение — объекты загружаются с `x-amz-acl: public-read`.

Ограничения загрузки: до 8 МБ, форматы JPEG, PNG, WebP, AVIF, SVG.

## Заявки и вебхук

Формы отправляют `POST /api/leads`. Сервер проверяет данные схемой Zod,
**пересчитывает стоимость заново** из настроек калькулятора (значение из
браузера не используется) и сохраняет `Lead`.

Защита от спама: скрытое поле-приманка, минимальное время заполнения формы
(2,5 секунды) и ограничение 5 заявок с адреса за 10 минут. Подозрительные
заявки не отбрасываются молча — они сохраняются со статусом «Спам», чтобы
ложное срабатывание можно было заметить.

Если задан вебхук — в админке (Настройки → Webhook для заявок) или переменной
`LEAD_WEBHOOK_URL` — на каждую заявку уходит `POST` с JSON. Значение из админки
имеет приоритет. Секрет передаётся в заголовке `X-Webhook-Secret`. Результат
доставки виден в карточке заявки. Отправка не задерживает ответ пользователю.

Формат тела:

```jsonc
{
  "id": "clx…",
  "createdAt": "2026-08-10T09:00:00.000Z",
  "name": "Иван",
  "phone": "+7 953 558-89-99",
  "email": null,
  "message": null,
  "source": "CALCULATOR",
  "calculator": {
    "budget": { "from": 2000000, "to": 3500000 },
    "choices": [{ "key": "format", "question": "…", "values": ["full"], "labels": ["Комплексный подбор"] }],
    "estimate": { "price": 14500, "priceFrom": 12500, "priceTo": 16500, "reserve": 175000 }
  },
  "utm": { "source": null, "medium": null, "campaign": null, "content": null, "term": null },
  "pageUrl": "https://…"
}
```

## Сборка и деплой

```bash
npm run check     # eslint + tsc --noEmit
npm run build     # prisma generate + next build
npm run start
```

Порядок на production-сервере:

```bash
npm ci
npm run db:deploy
npm run build
npm run start
```

Обязательно задать `NEXT_PUBLIC_SITE_URL` (иначе canonical и sitemap уйдут на
localhost) и `AUTH_SECRET`.

Главная страница обслуживается через ISR с интервалом 5 минут; сохранение в
админке сбрасывает кэш немедленно.

## Админ-панель

`/admin`. Разделы:

**Сводка** — счётчики заявок, предупреждение о недоступной базе, счётчик
демонстрационных данных со ссылками на их замену.

**Заявки** — фильтр по статусу, поиск по имени, телефону и тексту, смена
статуса, заметка менеджера, параметры расчёта, UTM-метки, результат доставки
вебхука.

**Контент** — Секции и заголовки, Главный экран, Акции, Услуги,
Что проверяем, Калькулятор, Автомобили, Этапы работы, Почему доверяют,
Разборы, Отзывы, Вопросы и ответы.

Акция — это карточка с ценой по акции против зачёркнутой обычной, кнопкой в
мессенджер и сроком действия. Срок вводится текстом («1 декабря 2026 года»),
чтобы его можно было написать как угодно; автоматического скрытия по дате нет —
просто выключите акцию переключателем.

**Сайт** — Меню, Контакты, SEO, Настройки.

У списков: добавление, редактирование, удаление с подтверждением, публикация
через переключатель, сортировка перетаскиванием и кнопками (кнопки нужны для
работы с клавиатуры). Изображения загружаются через выбранное хранилище с
предпросмотром.

Раздел **Калькулятор** редактирует расчёт целиком: базовую стоимость, границы,
округление, ширину вилки, долю резерва, пороги по бюджету, шаги, варианты
ответа с коэффициентами и надбавками, дисклеймер и тексты экрана результата.

Формула:

```
итог = clamp( round( (базовая стоимость + Σ надбавок) × Π коэффициентов ) )
```

При множественном выборе (марки) берётся наибольший коэффициент, а не
произведение — иначе пять выбранных марок множили бы цену впятеро.

## Данные, которые необходимо заменить перед production

### 1. Параметры калькулятора — требуют согласования

Формула расчёта заказчиком **не предоставлена**. Все числа в
`src/content/defaults.ts` (`DEFAULT_CALCULATOR`, `DEFAULT_BUDGET_TIERS`,
коэффициенты вариантов) — демонстрационные и подобраны только для того, чтобы
блок работал.

Согласовать и внести в админке (Калькулятор): базовую стоимость, минимум и
максимум оценки, шаг округления, ширину вилки, долю резерва на обслуживание,
пороги по бюджету, коэффициенты и надбавки каждого варианта.

До согласования на экране результата показывается дисклеймер о предварительном
характере расчёта.

### 2. Демонстрационный контент — помечен `isDemo`

| Что | Где заменить | Пометка на сайте |
| --- | --- | --- |
| 2 акции | Админка → Акции | бейдж «Демо» в углу карточки |
| 6 автомобилей | Админка → Автомобили | бейдж «Демо» на карточке |
| 3 отзыва | Админка → Отзывы | «DEMO ·» в имени, бейдж, сноска |
| 1 разбор автомобиля | Админка → Разборы | «DEMO ·» в тексте, бейдж |

Счётчик демонстрационных записей выведен на главную страницу админки.
Если реальных данных пока нет — выключите секцию целиком в разделе
«Секции и заголовки», это корректный сценарий: блоки скрываются без пустот.

### 3. Изображения

Все фотографии — стоковые с Unsplash (Unsplash License, допускает коммерческое
использование). Подобраны по смыслу секции, но это не съёмка клиента.
Заменить на собственные фотографии автотехцентра, процесса диагностики и
переданных автомобилей через загрузку в админке.

Отдельно: **главный экран**. Слои собраны из стокового кадра Porsche Panamera
(Unsplash) скриптом `build-hero-planes.mjs` — см. раздел «Слои главного
экрана». Замените исходник на съёмку клиента и перезапустите скрипт:
`assets/hero-source.jpg` → `node scripts/build-hero-planes.mjs assets/hero-source.jpg`.

Если заказчик предоставит автомобиль, уже вырезанный с прозрачным фоном,
его можно загрузить прямо в админке (Главный экран → Слой 4) — переключатель
«Автомобиль вырезан» уже включён, маска не применяется.

Заголовок главного экрана набирается крупным Unbounded в верхнем регистре,
две строки. Кегль ограничен так, чтобы самая длинная строка (около 11.2em)
помещалась в контейнер: при замене текста держите строки в пределах
12–13 символов, иначе строка перенесётся. Третью строку можно вернуть,
заполнив поле «Заголовок, строка 3».

### 4. Утверждения клиента, требующие подтверждения

Перенесены с действующего сайта дословно, но их стоит перепроверить перед
публикацией:

- «Мы работаем в этой сфере уже минимум десять лет»;
- «Проверка автомобиля осуществляется почти по сотне характеристик»;
- упоминание партнёра ExpertAuto52.

Ничего сверх этого не добавлялось. В текстах нет количества клиентов, процентов
успешных подборов, гарантий, сроков и цен — таких данных заказчик не предоставил.

### 5. Юридические документы

`/privacy` и `/consent` — типовые заготовки, а не готовые документы. Требуют
проверки юристом и указания полного наименования оператора, ИНН и ОГРН
(вносятся в админке → Настройки). На самих страницах выведено соответствующее
предупреждение.

### 6. Прочее

- Карта в контактах — виджет Яндекс.Карт по текстовому запросу. Для точной метки
  задайте координаты в Настройках (широта и долгота).
- Ссылки на мессенджеры пусты, поэтому кнопки не показываются. Заполните
  WhatsApp / Telegram в Настройках, если они нужны.
- Логотип отрисован текстом в фирменной типографике. Загрузите файл в
  Настройках, чтобы заменить.
- `AUTH_SECRET` в `.env` для разработки — заведомо небезопасное значение,
  на production обязательно сгенерировать новое.

## Типографика и оформление

Заголовки — **Unbounded Bold**, основной текст — **Manrope**, служебные подписи
(метки характеристик, «Демо») — **JetBrains Mono**. Все три с кириллицей,
подключаются через `next/font/google` с локальным хостингом файлов.

Надзаголовков и порядковых номеров секций на сайте нет: секцию представляет
только крупный заголовок. Поле «Надзаголовок» убрано из форм админки, колонка
`eyebrow` осталась в базе ради совместимости. Номер сохранён единственно в
счётчике шагов калькулятора — там это навигация по форме.

Главный экран собран по механике reference osmosupply/parallax-scrolling:
четыре слоя в `[data-parallax-layers]`, один общий scrub-таймлайн,
`yPercent` 70 / 55 / 40 / 10. Слой заголовка лежит под слоем автомобиля.

### Слои главного экрана

В reference одна фотография горы разложена на планы — небо, гора, передний
гребень. Здесь то же самое сделано для автомобильного кадра:

```bash
node scripts/build-hero-planes.mjs assets/hero-source.jpg
```

Скрипт кладёт в `public/hero/`:

| Файл | Что это |
| --- | --- |
| `sky.webp` | небо, растянутое вниз и приведённое к палитре (подложка, 12 КБ) |
| `car.webp` | всё ниже линии горизонта: дорога, деревья, автомобиль (с прозрачностью, 240 КБ) |
| `og.jpg` | те же планы, сведённые в кадр 1200×630 для соцсетей |

Небо ищется связной заливкой от верхней кромки, а не порогом по всему кадру:
порог в лоб пробивает дырки в тёмных участках кузова. Перед сборкой альфы
область неба расширяется на 4 пикселя — иначе по контуру кузова и деревьев
остаётся светлый ореол от старого, почти белого неба.

**Требования к исходному кадру:** автомобиль снят на фоне открытого неба,
небо заметно светлее остального. Скрипт проверяет это сам и отказывается
работать, если контраст меньше 60 единиц яркости или заливка протекла
в объект.

**Ограничение текущего кадра.** Из него получаются только два плана: небо и
всё остальное. Автомобиль занимает 14–87% ширины, поэтому «средней
дистанции» за ним просто нет — попытка вырезать третий план (полосу деревьев)
оставляла в кроне дыру, которая выезжала из-за кузова на скролле.

В reference планов три, и глубина читается именно за счёт того, что дальняя
гора и ближний гребень — оба детальные и движутся с разной скоростью. Чтобы
получить то же самое, нужен **кадр с реальной средней дистанцией**: автомобиль
на дороге, а за ним — отдельно стоящая линия города, гор или леса, не
перекрытая кузовом. Тогда скрипт можно будет расширить на третий план.

Сейчас перепад скоростей держат заголовок (40%) и автомобиль (10%), а слой
дымки получил световые полосы у горизонта — у бесформенного градиента нет
кромок, и его сдвиг на 55% глазом не читается.

### Выход из главного экрана

Сцена должна **проваливаться в темноту**, а не упираться в светлый блок —
в этом суть эффекта reference. Поэтому полоса доверия под hero тоже тёмная
(`bg-ink`), а возврат к светлому контенту сделан градиентом высотой 96–160px
в конце этой секции, а не границей между блоками.

Если менять порядок секций, следите за тем, чтобы сразу под hero оставалась
тёмная секция: стык `ink → paper` вплотную читается как обрыв.

### Про грейдинг неба

Плита неба показывается через `object-cover`, и видна только её **верхняя
часть** — ниже всё закрывает план с автомобилем. Поэтому свет собран в полосе
30–52% высоты плиты; подсвет у нижнего края был бы не виден вообще.

Полоса свечения намеренно широкая: на широком экране плита масштабируется по
ширине, на узком — по высоте, и одна и та же доля высоты попадает на разные
места сцены. Узкая полоса ложилась на горизонт только на десктопе.

Посадка планов в сцене (`.parallax__car` в `globals.css`) рассчитана на то,
что в плите небо занимает верхние 19.3%, дальше идёт крыша, на 30.5% —
кромка деревьев. При замене кадра эти доли изменятся — проверьте, что
последняя строка заголовка по-прежнему уходит за кузов.

## Доступность и производительность

- `prefers-reduced-motion` отключает параллакс, Lenis, появление блоков,
  набор чисел и доводку карусели.
- Карусель управляется стрелками, Home и End; активный слайд объявляется
  через `aria-live`.
- Калькулятор построен на нативных `radio` и `checkbox` внутри `fieldset` —
  стрелки и пробел работают штатно; после перехода фокус переносится на
  заголовок шага.
- Вкладки «Что проверяем» реализованы по WAI-ARIA с roving tabindex.
- Ответы FAQ всегда присутствуют в DOM (скрыты высотой, а не удалением) —
  разметка `FAQPage` совпадает с тем, что видит робот.
- Страница — серверный компонент; клиентскими являются только шесть островов.
- Горизонтальной прокрутки нет ни на одном брейкпоинте (проверено измерением
  на 375 и 1440 px).
