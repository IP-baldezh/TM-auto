### 1.3 osmosupply / parallax-scrolling — механика hero

Взята именно механика, а не картинка:

- слои лежат в одном контейнере `[data-parallax-layers]`, каждый помечен
  `data-parallax-layer="N"`;
- один общий `gsap.timeline` со `scrollTrigger` и `scrub` двигает все слои
  одновременно, добавляя твины в позицию `"<"`;
- разная величина `yPercent` даёт разную скорость: больше значение — слой
  сильнее уезжает вниз — воспринимается дальше;
- Lenis подключён к `ScrollTrigger.update` через `gsap.ticker`.

Разметка воспроизведена один в один, включая имена классов: `.parallax` →
`.parallax__header` → `.parallax__visuals` → `[data-parallax-layers]` →
четыре слоя, `.parallax__fade`, `.parallax__black-line-overflow`.
Значения `yPercent` взяты из reference без изменений: 70 / 55 / 40 / 10.

Отличия под задачу:

- содержимое автомобильное: слой 1 — город на закате, слой 2 — свет и дымка
  (только CSS), слой 3 — заголовок, слой 4 — автомобиль;
- заголовок лежит **под** автомобилем (у Osmo — под передней скалой), поэтому
  последняя строка уходит за кузов;
- Lenis не создаётся заново: единственный экземпляр живёт в `MotionProvider` и
  уже связан со `ScrollTrigger`, второй инстанс конфликтовал бы с первым;
- всё выключается при `prefers-reduced-motion`;
- вступительная анимация создаётся только для видимой вкладки: `gsap.from()`
  сразу выставляет нулевую прозрачность, а в фоновой вкладке
  `requestAnimationFrame` не вызывается — главный экран остался бы пустым.

### Геометрия слоёв — из оригинального CSS

Оригинальный CSS Osmo найден в его демо на CodePen и сохранён целиком в
[`docs/osmo-reference.css`](osmo-reference.css). До этого геометрия слоёв
писалась «на глаз», и именно в ней была причина, почему эффект не совпадал:

| | Оригинал | Было у нас |
| --- | --- | --- |
| `.parallax__visuals` | `height: 120%` | `100%` |
| `.parallax__layer-img` | `height: 117.5%`, `top: -17.5%` | `inset: 0` |
| `.parallax__layer-title` | `height: 100svh`, flex-центр | центр со сдвигом |
| `.parallax__title` | `11vw`, по центру | `7.8vw`, слева |
| `.parallax__fade` | `20%`, 13 стопов градиента | `32–46svh`, 2 стопа |
| `.parallax__radial-gradient` | есть | не было |

Ключевое — **слои выше кадра и подняты над ним**. Каждый слой простирается от
−21svh до 120svh, поэтому может уехать вниз на 70% своей высоты и не обнажить
пустоту. Слои, обрезанные ровно по кадру, просто уползают за границу — отсюда
и было вялое движение.

Два осознанных отступления от оригинала, оба продиктованы содержимым кадра:

- `object-position: center top` на слоях. У Osmo передний план занимает низ
  плиты и обрезка по центру попадает верно; у нашего кадра содержимое выше.
- Отдельные высота и смещение переднего плана на экранах уже 768px: почти
  квадратная плита в узком высоком контейнере обрезалась до 31% ширины.

### Слои: как в reference

Разбор файлов reference показал главное: три его слоя — это **одна фотография
2000×1906, разрезанная на планы** (у первого нет альфа-канала, у двух других
есть). Небо, гора, передний гребень с фигурой — не отдельные картинки, а
послойная разборка одного снимка.

То же самое сделано здесь скриптом `scripts/build-hero-planes.mjs`:
автомобильный кадр разрезается на `sky.webp` (небо, растянутое вниз и
приведённое к палитре) и `car.webp` (всё ниже линии горизонта — дорога,
деревья, автомобиль, с прозрачностью).

Небо ищется связной заливкой от верхней кромки. Порог по яркости в лоб не
годится: он пробивает дырки в тёмных участках кузова, а через блики и стёкла
заливка утекает в весь кадр — проверено, первые попытки давали именно это.
Перед сборкой альфы область неба расширяется на 4 пикселя, иначе по контуру
остаётся светлый ореол от исходного, почти белого неба.

Небо обязательно выносится из подложки: планы разъезжаются на скролле, и если
оставить полный кадр фоном, в глубине проступит второй, «призрачный»
автомобиль.

Посадка планов рассчитана по замеренным долям плиты: небо — верхние 19.3%,
крыша — 19.3%, кромка деревьев — 30.5%. Проверено на четырёх разрешениях, что
первая строка заголовка лежит выше крыши, а последняя её пересекает.

### 1.4 ruixen.ui / coverflow-carousel — механика карусели

Ключевые решения оригинала сохранены как есть, потому что они правильные:

- дробная позиция хранится в `ref`, а не в состоянии React — шестьдесят
  перерисовок в секунду ради чисел, которые нужны только DOM, не нужны;
- зацикливание реализовано сворачиванием расстояния по кольцу
  (`offset > count/2 → offset -= count`), без клонирования узлов;
- доводка — экспоненциальное затухание к цели (`pos += remaining * 0.16`);
- наклон и уход вглубь ослабевают по степенно́му закону (`falloff = 0.56`),
  иначе вторая карточка складывается почти в ребро.

Добавлено: деградация при числе карточек меньше трёх (кольцо отключается),
определение оси жеста (горизонталь — карусели, вертикаль — странице),
`prefers-reduced-motion`, клавиши Home/End, объявление активного слайда
через `aria-live`.

## 2. Дизайн-направление

**Формула:** modern automotive / engineering premium. Ощущение технической
службы, а не автосалона и не SaaS-продукта.

### Палитра

Выведена из фирменного стиля клиента: красный `#C60F13` взят из логотипа и
таблицы стилей действующего сайта, графит и тёплый белый — оттуда же.

| Токен | Значение | Роль |
| --- | --- | --- |
| `--color-paper` | `#F4F1EC` | основной фон, тёплый белый |
| `--color-ink` | `#0E1114` | текст, тёмные секции |
| `--color-graphite` | `#171C21` | вторая тёмная поверхность |
| `--color-steel` | `#5B6670` | вторичный текст |
| `--color-line` | `#D8D2C8` | волосяные линии |
| `--color-brand` | `#C60F13` | CTA, активные состояния, индексы |

Красный дозирован: заливка основной кнопки, активная вкладка, полоса прогресса,
индексы, короткие подчёркивания. Нигде не используется как фон крупных площадей.

### Типографика

- **Unbounded Bold (700)** — все заголовки сайта. Широкий геометрический
  гротеск с полноценной кириллицей, хорошо держит крупный кегль.
  `letter-spacing: -0.02em` (сильный отрицательный трекинг ему вредит).
  Заголовок главного экрана — в верхнем регистре,
  `clamp(2.125rem, min(9.6vw, 13svh), 9.5rem)`: ограничение и по ширине, и по
  высоте экрана, чтобы три строки помещались на невысоком ноутбуке.
- **Manrope** — основной текст и интерфейс.
- **JetBrains Mono** — только служебные подписи: метки характеристик
  автомобиля, «Демо», названия полей в контактах.

В админке заголовки переключены обратно на Manrope (`[data-admin]`):
широкий дисплейный шрифт мешает плотности служебного интерфейса.

### Структурные мотивы (вместо шаблонной эстетики)

- волосяная линия 1px как основной разделитель — не рамки карточек;
- короткая красная черта перед заголовком вместо надзаголовка;
- радиусы 3–5px, а не 16px; тени почти не используются;
- асимметричные сетки (7/5, 5/7) вместо равных колонок;
- крупная фотография как структурный элемент, а не иллюстрация в карточке.

**Надзаголовков и порядковых номеров секций нет.** Секцию представляет
только крупный заголовок; иерархию держат размер, волосяные линии и
красный акцент. Поле `eyebrow` осталось в базе ради совместимости, но не
выводится и убрано из форм админки.

Сознательно **не использовано:** glassmorphism, фиолетово-синие градиенты,
светящиеся сферы, blob-фоны, одинаковые bento-плитки, декоративные графики.

### Сетка

Контейнер `max-width: 1320px`, боковые отступы 20 / 32 / 40px по брейкпоинтам.

## 4. Архитектура компонентов

Принцип: **страница — серверный компонент**; клиентскими становятся только
острова, которым действительно нужен браузер.

```
app/
  (site)/            публичная часть
    layout.tsx       Header, Footer, MotionProvider
    page.tsx         Server Component: собирает секции
    privacy/, consent/
  admin/
    login/           открытая страница входа
    (protected)/     всё остальное — за проверкой сессии
  api/
    leads/           приём заявок
    admin/upload/    загрузка изображений
```

### Клиентские острова

| Компонент | Почему клиентский |
| --- | --- |
| `ParallaxHero` | GSAP ScrollTrigger |
| `CoverflowCarousel` | ручное управление трансформациями, жесты |
| `Calculator` | пошаговое состояние |
| `InspectionExplorer` | вкладки с roving tabindex |
| `ProcessTimeline` | IntersectionObserver |
| `FaqAccordion`, `Header`, `FinalCta` | состояние раскрытия / форма |

Остальное — серверные компоненты. Появление блоков при скролле сделано **без**
превращения секций в клиентские: `MotionProvider` вешает `ScrollTrigger.batch`
на атрибут `data-reveal`, который проставляется в серверной разметке.

### Слой данных

```
prisma → lib/content.ts (view-модели) → компоненты
              ↓ база недоступна
       src/content/defaults.ts
```

Компоненты не импортируют типы Prisma. Это позволяет отдавать те же данные из
`defaults.ts`, когда базы нет: сборка и сайт не падают, а админка показывает
предупреждение.

`src/content/defaults.ts` — единственный источник содержимого «из коробки»,
используется и сидером, и рантаймом. Дублирования нет.

### Движок калькулятора

`lib/calculator/engine.ts` — чистая функция без React и Prisma:

```
итог = clamp( round( (baseFee + Σ addend) × Π multiplier ) )
```

Выполняется дважды: в браузере для мгновенного результата и на сервере при
приёме заявки. Значение из браузера не используется — подделать сумму в CRM
нельзя.

## 5. Модель данных

**Выбрана Prisma, не Drizzle.** Обоснование:

1. Контент-модель — это 20 небольших таблиц с CRUD, а не сложные аналитические
   запросы. Сильная сторона Drizzle (близость к SQL, точный контроль запроса)
   здесь не востребована; сильная сторона Prisma (генерируемый клиент, `upsert`,
   миграции, `prisma studio` как аварийный доступ для менеджера) — востребована.
2. `prisma migrate` даёт версионированные SQL-миграции без ручного написания DDL.
3. Соседний проект заказчика собран на Prisma — единый инструментарий эксплуатации.
4. Технически: Prisma 7 требует Node `^20.19 || ^22.12 || >=24`, на машине
   разработки Node 20.13 — поэтому зафиксирована версия **6.19.3**.

### Принцип раскладки

- **Синглтоны** с фиксированной композицией — своя таблица:
  `HeroSection`, `CalculatorConfig`, `SiteSettings`, `SeoSettings`.
- **Списки** — таблица с `sortOrder` и `enabled`.
- **Заголовки и видимость остальных секций** — общая таблица `SectionBlock`
  (`key`, `eyebrow`, `title`, `subtitle`, `enabled`, `sortOrder`). Это убирает
  двенадцать таблиц из трёх текстовых полей каждая.
- `Json` использован ровно там, где структура свободная: `CalculatorStep.rangeConfig`
  и `Lead.calculatorData`. Списки строк — нативные массивы PostgreSQL (`String[]`).

### Таблицы

| Группа | Модели |
| --- | --- |
| Доступ | `AdminUser`, `Session` |
| Каркас | `SectionBlock`, `NavigationItem`, `SiteSettings`, `SeoSettings` |
| Контент | `HeroSection`, `TrustItem`, `InspectionCategory`, `Service`, `ProcessStep`, `TrustReason`, `CaseStudy`, `Testimonial`, `FaqItem`, `DeliveredCar`, `ContactChannel` |
| Калькулятор | `CalculatorConfig`, `CalculatorStep`, `CalculatorOption`, `CalculatorBudgetTier` |
| Заявки | `Lead` |

`Session` хранит не токен, а его HMAC-отпечаток (ключ — `AUTH_SECRET`):
дампа базы недостаточно, чтобы выпустить действующую сессию.

| Этап | Статус |
| --- | --- |
| Разбор четырёх референсов, извлечение фактов клиента | выполнено |
| Дизайн-направление, палитра из фирменного стиля | выполнено |
| Схема БД, миграция, сид | выполнено |
| Hero: пятислойный параллакс | выполнено, проверено измерением геометрии |
| Coverflow: 3D-карусель | выполнено, проверено с клавиатуры |
| Калькулятор: 6 шагов + движок | выполнено, расчёт сверен с формулой |
| Остальные секции | выполнено |
| Админка, авторизация, заявки | выполнено (см. ограничение ниже) |
| SEO, разметка, sitemap, robots | выполнено |
| lint / typecheck / build | проходят |
| Проверка desktop / mobile | выполнено |

**Ограничение проверки:** на машине разработки не запущены ни PostgreSQL, ни
Docker, поэтому путь «с базой» (миграция → сид → вход в админку → CRUD →
сохранение заявки) не выполнялся вживую. Проверено то, что от базы не зависит:
схема компилируется в корректный DDL (22 таблицы, 5 типов), сайт работает на
значениях по умолчанию, админка закрыта редиректом, загрузка файлов без сессии
даёт 401, валидация заявки возвращает ошибки по полям, а при недоступной базе —
понятное сообщение с предложением позвонить.
